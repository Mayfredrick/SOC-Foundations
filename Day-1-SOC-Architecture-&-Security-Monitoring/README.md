#Day 1 – SOC Architecture & Security Monitoring

## Overview
This lab introduced the basic structure and responsibilities of a Security Operations Center (SOC). The goal was to understand how security teams monitor systems, detect suspicious activity, investigate alerts, and respond to cybersecurity incidents.
I also reviewed the roles of SIEM, IDS, EDR, Security Onion, Wazuh, Suricata, and Zeek.

## 1. What is a SOC?

A Security Operations Center (SOC) is responsible for monitoring, detecting, investigating, and responding to cybersecurity incidents within an organization.

A SOC helps security teams identify suspicious activity, investigate potential threats, and take appropriate actions to reduce the impact of security incidents.

### Main SOC responsibilities

* Monitor security events
* Detect suspicious activity
* Investigate alerts
* Analyze security data
* Identify indicators of compromise (IOCs)
* Respond to security incidents
* Escalate serious incidents
* Document investigations

## 2. SIEM vs IDS vs EDR

### SIEM
A Security Information and Event Management (SIEM) platform collects and analyzes log data from different systems and devices.

Examples of information that can be collected include:
* Windows event logs
* Authentication events
* Application logs
* Firewall logs
* Network security events

The goal is to centralize security information so analysts can investigate activity across the environment.

### IDS
An Intrusion Detection System (IDS) monitors network traffic for suspicious or potentially malicious activity.
An IDS can generate alerts when network traffic matches known attack patterns or other detection rules.

### EDR
Endpoint Detection and Response (EDR) provides security monitoring and response capabilities for endpoint devices.
EDR can help security teams investigate activity occurring on computers and servers, including suspicious processes, network connections, and other endpoint behavior.

### Comparison
| Technology | Primary Purpose                          |
| ---------- | ---------------------------------------- |
| SIEM       | Collect and analyze security logs        |
| IDS        | Detect suspicious network activity       |
| EDR        | Monitor and respond to endpoint activity |

## 4. Wazuh
Wazuh is a free and open-source security platform that provides unified XDR and SIEM capabilities.
The Wazuh platform uses an agent and central components including:
* Wazuh agent
* Wazuh server
* Wazuh indexer
* Wazuh dashboard

Wazuh can provide capabilities such as log analysis, intrusion and malware detection, file integrity monitoring, configuration assessment, and vulnerability detection.

## 6. Zeek

Zeek is a network security monitoring and network analysis framework.
Rather than primarily functioning as a traditional signature-based IDS, Zeek provides detailed network metadata that can help analysts understand what is happening on a network.
Examples include information about:
* DNS
* HTTP
* SSH
* SSL
* FTP
* Network connections

Security Onion uses Zeek for network protocol analysis and metadata.

### Why Zeek is important
Suricata can tell the analyst that suspicious activity was detected.
Zeek can provide additional network context that helps the analyst understand the communication taking place.

## 7. Logs vs Alerts

### Logs
Logs are records of activities generated by systems, devices, applications, or security tools.

Examples include:
* User logins
* Network connections
* Application activity
* System changes
* Authentication attempts

### Alerts
An alert is generated when an event matches a security rule or appears suspicious enough to require attention or investigation.

### Comparison

| Logs                                     | Alerts   
-------------------------------------------------------------------------                                     
| Record activity                          | Identify activity requiring attention                                  |
| Can contain large amounts of information | Usually more focused                          |
| Used for investigation                   | Used to prioritize investigation                              |
| May not indicate a security problem      | May indicate suspicious or malicious activity                         |

## 8. Events vs Incidents

### Event
An event is an occurrence that happens within a system or environment.
Events can be:
* Planned
* Unplanned
* Normal
* Suspicious
* Security-related
* Non-security-related

### Incident
A security incident is an event or series of events that requires investigation and potentially a response because it may affect the security or normal operation of an environment.

## 9. What is Triage?
Triage is the process of quickly assessing, prioritizing, and responding to security alerts or incidents.

The goal is to determine which alerts require immediate attention and which can be investigated later or closed.

### Triage considerations
An analyst may consider:
* Severity
* Affected system
* User involved
* Source IP
* Destination IP
* Time of activity
* Indicators of compromise
* Known malicious behavior
* Potential business impact

### Example
If a SOC receives 100 alerts, the analyst should not automatically treat all 100 as equally serious.
The analyst should prioritize alerts based on risk and available evidence.

## 10. SOC Analyst Investigation Process
The SOC analyst investigation process can be summarized as:
Alert
  |
  v
Validate Alert
  |
  v
Understand Baseline Behavior
  |
  v
Analyze Anomalies
  |
  v
Look for IOCs
  |
  v
Correlate Evidence
  |
  v
Determine Severity
  |
  +----------------+
  |                |
  v                v
Close           Escalate
                   |
                   v
              Response/
              Containment


### Investigation steps

1. Validate the alert
   Determine whether the alert is legitimate or a false positive.

2. Understand normal behavior
   Compare the activity with expected system or user behavior.

3. Analyze anomalies
   Identify activity that differs from the normal baseline.

4. Search for IOCs
   Look for indicators such as suspicious IP addresses, domains, files, hashes, or processes.

5. Correlate evidence
   Compare information from multiple sources.

6. Determine severity
   Consider the likelihood and potential impact of the activity.

7. Close or escalate
   Close the alert if there is no security concern.
   Escalate when additional investigation or response is required.

8. Contain and respond
   If appropriate, take actions to limit the threat and prevent further damage.
